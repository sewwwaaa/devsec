1. Executive Summary & System Overview

1.1 Selected Application & Rationale (Appendix A.1 Compliance)

Modern software development demands a fundamental paradigm shift from legacy "perimeter-only" security towards an automated, continuous DevSecOps pipeline where security practices are embedded throughout every phase of the Software Development Life Cycle (SDLC). To operationalise these concepts without reliance on commercial cloud subscriptions or complex Kubernetes clusters, our group selected OWASP NodeGoat, pre-vetted and recommended under Appendix A.1 (Intentionally Vulnerable Applications) of the IE3142 module brief.

As noted in the assignment brief, selecting an approved intentionally vulnerable application allows groups to focus limited time on the pipeline and remediation work rather than on vulnerability discovery; the flaws are documented, realistic, and mapped to known CWE/OWASP categories, which makes the Section 2.3 exploit-and-fix requirement far more predictable to plan and demonstrate.

Core Constraints Verification:
  • Communicating Components: Distinct web presentation/API tier (Node.js/Express) communicating over TCP with a MongoDB document database.
  • Containerisation: Fully containerised with a dedicated Dockerfile and multi-container docker-compose.yml orchestration.
  • Offline Capability: Operates 100% offline on local developer workstations without cloud dependencies.
  • Authentic Vulnerability Demonstrations: Native OWASP Top 10 vulnerabilities (SSJS, NoSQL Injection, Stored XSS, Broken Auth) verified via exploits, SAST, and permanent code fixes.

1.2 Technology Stack

  • Web Tier: Node.js runtime, Express.js web framework, Swig/HTML server-side templating, session cookies.
  • Database Tier: MongoDB 4.4 NoSQL document store with collections for users, allocations, memos, and counters.
  • Security Automation Toolchain:
    • SAST: Semgrep CLI (p/owasp-top-ten, p/nodejs, p/security-audit).
    • SCA: npm audit dependency scanning.
    • Secrets Scanning: Gitleaks Action v2.
    • Container Image Scanning: Aqua Security Trivy Action (v0.24.0).

1.3 System Architecture & Trust Boundaries

  • Trust Boundary 1 (Public Client to Ingress): Ingress on port 4000 exposed to public browser traffic and external adversaries.
  • Trust Boundary 2 (Express Web Application Container): Session validation, routing to controllers (contributions.js, allocations.js, memos.js, profile.js), and view rendering.
  • Trust Boundary 3 (Application-to-Database Boundary): Isolated bridge network (nodegoat-net) connecting Express to MongoDB on port 27017 via Data Access Objects.
  • Trust Boundary 4 (Secrets & Configuration Boundary): Sensitive keys injected via environment variables and GitHub Actions encrypted secrets; zero hardcoded secrets in git.

3. Secure Coding: Exploit-and-Fix Walkthrough (LO2)

3.1 Vulnerability 1: Server-Side JavaScript (SSJS) Injection in Contributions

CWE Mapping: CWE-94 / CWE-95 — OWASP Top 10 A1: Injection.

Root Cause: User inputs in app/routes/contributions.js were parsed via eval():

// Insecure evaluation
const preTax = eval(req.body.preTax);

Exploit Demonstration: Intercepted POST to /contributions with payload:

preTax=10; res.end(require('child_process').execSync('whoami').toString())&afterTax=5&roth=5

The server executed the command and streamed the server's OS username back in the HTTP response, proving Remote Code Execution (RCE).

Secure Coding Fix (Commit 22574e5):

- const preTax = eval(req.body.preTax);
+ const preTax = parseInt(req.body.preTax, 10);

Re-attempt & SAST Result: Payload returns inert integer 10. Semgrep finding eval-with-expression resolved from 1 finding to 0 findings.

3.2 Vulnerability 2: NoSQL Injection in Allocations

CWE Mapping: CWE-943 — OWASP Top 10 A1: Injection.

Root Cause: Concatenation into a MongoDB $where clause in app/data/allocations-dao.js.

Exploit Demonstration: Sent GET /allocations/2?threshold=1';+return+1=='1, forcing $where to evaluate to true for all documents, leaking all employee retirement portfolios.

Secure Coding Fix: Replaced dynamic $where evaluation with native parameterized MongoDB operators: { userId: parsedUserId, stocks: { $gt: parsedThreshold } }.

Re-attempt & SAST Result: Payload causes invalid threshold error. Semgrep NoSQL injection findings reduced to 0.

3.3 Vulnerability 3: Stored Cross-Site Scripting (XSS) in Memos

CWE Mapping: CWE-79 — OWASP Top 10 A7: Cross-Site Scripting.

Root Cause: In app/views/memos.html, memos were rendered via marked(doc.memo) without sanitization.

Exploit Demonstration: Posted memo with <img src="x" onerror="alert(document.cookie)">, executing script upon browsing to /memos.

Secure Coding Fix: Configured marked.setOptions({ sanitize: true, escape: true }).

Re-attempt & SAST Result: Script tags safely escaped as text (&lt;img...&gt;). Semgrep finding cleared.

3.4 Vulnerability 4: Plaintext Password Storage & Hardcoded Secrets

CWE Mapping: CWE-256 / CWE-798 — OWASP Top 10 A2: Broken Authentication.

Root Cause: Passwords stored in plaintext in app/data/user-dao.js and session secret hardcoded in config/env/all.js.

Secure Coding Fix: Implemented bcrypt.hashSync(password, bcrypt.genSaltSync(10)) and externalized session secret to process.env.SESSION_SECRET.

Verification: MongoDB database query verifies passwords stored as irreversible hashes. Gitleaks scan reports 0 findings.

4. CI/CD Pipeline Design & Security Automation (LO3)

Our GitHub Actions workflow in .github/workflows/devsecops-pipeline.yml executes four automated security gates on every push:

  1. Gate 1 (SAST): Semgrep CLI scanning app/ using p/owasp-top-ten, p/nodejs, and p/security-audit.
  2. Gate 2 (SCA): npm audit analyzing package-lock.json dependencies.
  3. Gate 3 (Secrets): Gitleaks Action v2 scanning commit diffs and history.
  4. Gate 4 (Container Security): Aqua Security Trivy Action (v0.24.0) scanning the built nodegoat:latest image.
Pipeline Blocking Demonstration:
On a demonstration branch reintroducing an unhandled eval(), Semgrep detected 1 critical error. The workflow executed exit 1, terminating the pipeline and marking the GitHub Actions run as failed (Red Cross), genuinely blocking the bad build from deployment.

5. Secrets Management Approach

In accordance with Section 2.5, no credentials reside in the git repository. We enforce:

  • GitHub Actions Encrypted Secrets: Injects CI tokens into runner memory at execution time.
  • Runtime Environment Variables: Database connection strings and session keys passed via .env files excluded by .gitignore.
  • Pre-Commit & CI Gates: Gitleaks actively prevents secret leakage prior to merge.

6. Industry Trends & Case Study Analysis

Case Study: CircleCI Breach (January 2023): Attackers stole SSO tokens from an engineer's laptop, accessed CI/CD build environments, and stole customer secrets stored in environment variables.

Lessons Applied to NodeGoat: We enforce least-privilege ephemeral tokens, unprivileged container execution (USER node), and automated pre-deployment scanning (Gitleaks and Trivy) to catch vulnerabilities within minutes of commit.

7. Reflection & Future Improvements

  • Dynamic Application Security Testing (DAST): Integrating OWASP ZAP container into GitHub Actions for active endpoint probing.
  • Infrastructure as Code (IaC) Scanning: Integrating Checkov or tfsec to audit Dockerfiles for container security best practices.
  • Automated Pull Request Remediations: Integrating Dependabot for automated security patch PRs.
